# SSH 管理（@local/dsh-ssh-hosts）

一个 DSH Web 插件：在左侧面板列表的「自动化任务」入口下方加入 **SSH 管理**，打开后可以维护远程 SSH 主机、从 `~/.ssh/config` 导入、对主机做一次 SSH 连通性检查，并在右侧展开远程主机的文件夹列表。

## 功能

- **主机列表**：显示名称、`user@host:port`、连接状态与失败原因。
- **添加 / 编辑**：名称、主机、端口、用户、密钥文件、密码、私钥口令、跳板、默认工作区、远端 CLI 安装方式、API 密钥存放位置；支持「使用 `~/.ssh/config` 补全未设置的连接参数」。
- **远程文件夹**：点击行内的「文件夹」按钮，在列表右侧展开这台远程主机的目录树；可逐级展开、回到上级、刷新。新建主机保存后会自动展开。根目录取「默认工作区」，未设置时取远端 `~`。
- **远程文件编辑**：在目录树里**双击文件**（或选中后按 `Enter`）即在右侧面板内打开编辑器，可修改并保存回远端。`Ctrl/Cmd+S` 保存，`Tab` 插入两个空格，底部显示大小、行列号与行尾（LF/CRLF）、BOM 标记。只接受 UTF-8 文本、不含 NUL 字节、且不超过 1 MiB 的文件；其余情况只提示原因，不提供编辑。
- **从 `~/.ssh/config` 导入**：解析 `Host` 块、全局默认值、`Host *` 默认值和 `Include`（含通配符），在对话框里勾选后导入。
- **连接**：调用本机 OpenSSH 客户端执行一次有超时上限的连通性检查（`ssh ... true`），把结果与错误摘要显示在列表里。
- **删除**：删除主机记录，并一并删除 DSH 凭据中保存的密码/口令。

## 数据与安全

- 主机记录保存在 `$DSH_HOME/ssh-hosts/hosts.json`（默认 `~/.dsh/ssh-hosts/hosts.json`），文件权限 `0600`。
- 密码与私钥口令保存在 DSH 的 `credentials` 服务里，键为 `ssh-hosts/host-<id>`，**不会**写入 `hosts.json`。
- 连接检查通过 `ctx.subprocess` 以 argv 数组启动 `ssh`，不经过 shell；密码/口令通过一个权限为 `0700` 的临时 askpass 脚本和子进程环境变量传给 `ssh`。
- 首次连接使用 `StrictHostKeyChecking=accept-new`（TOFU），之后沿用 `known_hosts` 校验。
- 文件夹列表同样通过 `ssh` 执行一条只读命令：`cd -- <路径> && printf '%s\n' "$PWD" && LC_ALL=C ls -1Ap .`。路径以单引号转义后交给远端登录 shell，`~` 由远端展开而不是本地；命令不经过本地 shell，也不下载任何文件内容。单次列举最多返回 2000 项，超时上限 20 秒。
- `hosts.json` 允许带 UTF-8 BOM（PowerShell 的 `Set-Content` 会写入），读取时会自动去掉。
- 文件读写同样走 `ssh` + argv，路径以单引号转义，不经过本地 shell：
  - 读：`p='<路径>' && sha=$(sha256sum … || shasum -a 256 …) && head -c 1048577 "$p" | base64`，同时取回 sha256 与内容；`head -c` 只比 1 MiB 多读一个字节，所以超大文件不会整份传输。
  - 写：内容以 base64 从**子进程 stdin** 送入 `base64 -d > "$p"`，避免命令行长度上限，也避免任何文本编码/换行转换；写入后用 `sha256sum` 回读校验，摘要不一致就报错而不是假装成功。
- 保存是**原地覆盖**：`>` 截断写同一 inode，权限与属主保持不变；代价是非原子写，进程在写入中断时文件可能被截断。
- **冲突检测**：打开时记下远端 sha256，保存前再算一次；不一致返回 409，由用户选择覆盖或放弃自己的修改。
- **形状保留**：原文件带 BOM 就写回 BOM；原文件是纯 CRLF 行尾就还原成 CRLF（混用行尾的文件按 LF 处理，避免一次保存把整个文件重写成另一种行尾）。
- **危险路径**：写入 `/etc`、`/boot`、`/usr`、`/var/lib` 或任何 `.ssh` 目录时，保存前多一次确认。
- 保存上限 4 MiB（base64 后约 5.4 MiB stdin）；文件内容只在内存里流转，不落盘，也不会写进插件目录。

## 安装

包名 `@local/dsh-ssh-hosts`，本身就是一个 DSH bundle（`cordis.patch.yml` 会注册 `ssh-hosts` 条目）。

- **本地开发**：在 profile 的 `package.json` 依赖里写成 `"@local/dsh-ssh-hosts": "link:/path/to/dsh-ssh-remote"`，并在 `dsh.profile.bundles` 中列出。
- **从 GitHub 安装**：在 Web 的「插件」页安装或用 `plugin_manager` 工具 `install_bundle`，spec 为
  `https://github.com/SQDR2/dsh-ssh-remote.git`（也可用 `git+https://github.com/SQDR2/dsh-ssh-remote.git`）。
  如果所在网络无法直连 GitHub，可先在本地克隆再用 `link:` 方式。

## 使用

启用后刷新 Web 页面，在左侧面板列表的「自动化任务」下方点「SSH 管理」。或者直接在插件管理页看到 `SSH hosts` 条目。

在主机行上点「文件夹」按钮，右侧会展开这台主机的目录树：点击文件夹逐级展开，`↑` 回到上级，`⟳` 重新读取。新建主机并保存后会自动展开一次。

在目录树里双击一个文件即可打开编辑器：改完点面板右上角的保存按钮（或 `Ctrl/Cmd+S`）。左上角 `←` 返回目录树；有未保存修改时会先问「保存并返回 / 放弃修改 / 取消」。保存时如果远端文件已被别人改动，会提示「覆盖远端 / 放弃我的修改 / 取消」。

## 自检

```bash
node test/host.mjs     # 路由 / 转义 / ssh 参数 / BOM 容错 / 文件读写与冲突
node test/client.mjs   # 页面渲染、展开、折叠、关闭、打开编辑保存、冲突与危险路径
```

两个脚本都用假 Context / 假 subprocess / 假 React 驱动真实代码，不连接任何真实主机。

## 当前范围

「连接」是连通性检查，不会建立常驻的远程会话，也不会在远端启动 DSH。若后续需要真正的远程会话，可以在这个主机记录之上接入 `ctx.ssh` / `subprocess-ssh` 或打开远程终端。

文件夹面板的编辑能力只覆盖「打开 - 编辑 - 保存」，不新建、不重命名、不删除、不下载文件，也不跟随符号链接到目录之外；文件名按行解析，因此名称里带换行的极端文件会被拆成多行显示。远端需提供 POSIX 的 `sh`、`ls`、`base64`、`head`，以及 `sha256sum`（GNU）或 `shasum`（BSD/macOS）其中之一。

非 UTF-8 文件（例如 GBK 编码的旧配置）不会被打开：按 UTF-8 解码失败即拒绝编辑，以免保存后把文件写坏。文件超过 1 MiB 时同样只提示、不打开。编辑器是纯 `<textarea>`，没有语法高亮与行号。

「默认工作区」「远端 CLI 安装方式」「API 密钥存放位置」目前会保存在主机记录中，供后续远程会话能力使用，连通性检查不会读取它们。
